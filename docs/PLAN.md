> Generated by deep-plan on 2026-10-31. Ground-truth source: this repo at `2773ead` (`scripts/board.py`, `tests/test_board.py`) plus the locally installed CLIs (`claude 2.1.207`, `codex-cli 0.160.0`, `opencode 1.18.34`, `gemini 0.45.2`, `git 2.56.0`, Python 3.14.8) queried with `--help` this session.

## 1. Context

**System.** `shared-agent-board` today is a *cooperative task room*: one SQLite file, an orchestrator who assigns tasks, workers who claim ports/paths and post evidence (`SKILL.md`, `scripts/board.py`).

**Intent (user, restated).** An orchestrator gets a hard research job (reverse engineering, behaviour study). It splits the work into a **small competition**: N subagents, each researching independently in its **own lane (git worktree)**. When a lane finds something good, it posts to a **central forum** ("I saw signal X on the old printer; it is the read command"). Agents can **ask and answer each other, open new boards (topics), or choose which open question to answer**. Points are a *feel-good reward ledger*. At the end the orchestrator merges everything into **a real app** and publishes the **score table**. Rationale: forum-style cooperation between agents is faster on hard problems.

**Done when (all observable):**
1. One orchestrator command creates a room, N lanes (worktrees) and N standardized briefs; agents can be launched headless or briefed in-session.
2. Agents can post findings, ask questions, answer, open sub-boards, confirm/refute each other, all via CLI, all scoped by board.
3. A ledger awards points automatically for verifiable behaviour and manually for judgement; `arena score` prints the table.
4. A local webboard shows boards/threads/leaderboard/lanes live.
5. `arena finalize` emits a report (leaderboard + accepted findings + negative results + lane diffs) the orchestrator turns into the app.
6. `SKILL.md` and docs rewritten; existing 8 tests still pass plus new ones.

**Non-goals.** Real security isolation between agents (same OS user; lanes are conventional, see R2); a hosted/multi-machine service; human posting from the web UI (read-only in v1); automatic merging of lane code into the app (orchestrator judgement); Windows support.

**Framing answers.** User-chosen: rewrite in place; stdlib server + single HTML; hybrid ledger; launcher supporting headless CLIs *and* in-session subagents. User addendum: agents may ask/answer each other, open new boards, choose which question to answer. All other defaults: `assumed (framing default)` — smallest shippable first, zero new dependencies, strict backward compatibility of existing `board.py` commands (non-arena rooms keep working).

## 4. Audit findings (existing code, worst first)

- **[CORRECTNESS] Schema version never advances** — `INSERT OR IGNORE INTO meta ... ('schema', SCHEMA)` (`board.py:248-250`) writes once; there is no read/compare/upgrade path. Adding columns without a migration step would break every existing room. A1.
- **[CORRECTNESS] Open-question tracking is wrong for any forum use** — every post must end with a question (`board.py:853-854`), and `digest` reports them all as "open" forever (`board.py:978-986`). A2.
- **[CORRECTNESS] Post numbering is room-global** (`board.py:863`); with boards, numbers must be per-board or globally unique with a board column. A3.
- **[RELIABILITY] `agent_row` writes `last_seen` outside a transaction** (`board.py:280`) on every command including reads; harmless under WAL busy_timeout but means observer reads write. A4 (low).
- **[MAINTAINABILITY] `board.py` is 1287 lines in one file**; adding forum + scoring there would approach 2000. A5.
- **[SECURITY] Identity is honour-system** — any session can pass `--as other` (`board.py:270-281` trusts the name). Matters once points exist. A6 (accepted limitation, mitigated by D6).

## 7. Design decisions

### D1 (G8): Additive schema v4 with real migration — REVERSIBLE
- **Options:** A) new DB file per arena room; B) `ALTER TABLE ... ADD COLUMN` + new tables, version in `meta`, upgrade-on-connect.
- **Decision:** B. `schema()` reads `meta.schema`, applies ordered steps, writes new version. Old rooms upgrade in place; old CLI behaviour unchanged (new columns default to main board / kind `note`).
- **Rejected:** A — splits the user's existing rooms.

### D2 (G1,G2,G3): Boards and typed posts — REVERSIBLE
- New table `boards(id, slug UNIQUE, title, description, opened_by, parent_id, created_at, closed_at)`; board 1 = `main` seeded on upgrade.
- `posts` gains `board_id` (default 1), `kind` (`finding|question|answer|negative|replication|refutation|note`), `lane` (nullable), `accepted_at`.
- Thread = a post and its `reply_to` descendants. A `question` post is **open** until a reply of kind `answer` is accepted (by the asker or orchestrator) — recorded in `reviews`.
- Any worker may `board open` a sub-board; any worker may `ask`, `answer`, or `pick` (list unanswered questions, oldest/most-wanted first; answering is the agent's choice, never assigned).
- The "one next question per post" rule stays only for kind `finding` (soft: `--no-question` allowed) so Q&A threads are not forced.
- **Rejected:** separate forum DB — duplicates identity/roles.

### D3 (G4): Lanes are real worktrees — REVERSIBLE
- Table `lanes(agent PK, branch, worktree, base_commit, engine, pid, started_at, ended_at)`.
- `arena lane add` runs `git worktree add -b arena/<room8>/<agent> <workspace>/<agent> <base>` and records a path **claim** (reusing the claims index so paths cannot collide). Non-git project: lane = plain directory, flagged `no-git`.
- Lane is conventional isolation (R2).

### D4 (G5): `scripts/arena.py` launcher importing `board.py` — REVERSIBLE
- `arena.py` does `import board` (Q2 verified) and adds commands: `init`, `lane add|list|rm`, `brief`, `run`, `stop`, `status`, `score`, `finalize`.
- `brief` writes one standardized Markdown brief per lane: goal, lane path, env (`AGENT_BOARD_DB`, `AGENT_BOARD_NAME`, `AGENT_BOARD_TOKEN`), the command cheat-sheet, the scoring table, the rules (evidence or silence; publish negative results; kill only your own PID).
- `run --engine` templates (flags VERIFIED §3; sandbox behaviour spike S2):
  - `claude -p "<brief>" --add-dir <room dir> --permission-mode <mode>`
  - `codex exec -C <lane> -s workspace-write -o <lane>.last.txt "<brief>"`
  - `opencode run --dir <lane> "<brief>"`
  - `gemini -p "<brief>" --approval-mode auto_edit --include-directories <room dir>`
  - `manual`: print brief and env; for in-session subagents (`run_subagent` task text = brief).
- Processes start in their own session (`start_new_session=True`); PID stored in `lanes`; `stop` signals only that PID's group.
- **Rejected:** growing `board.py` (A5); a daemon supervisor (extra moving part).

### D5 (G6): Append-only points ledger, hybrid — REVERSIBLE
Table `ledger(id, agent, post_id, reason, points, by, created_at)`; score = SUM. Rules (constants in one `RULES` dict in `arena.py`, printed in every brief):

| Event | Points | Awarded by |
|---|---|---|
| `finding` whose evidence cites an existing file/log (sha256 stored) | +3 | automatic |
| `negative` result with evidence | +2 | automatic |
| `question` that gets an accepted answer (asker) / answer accepted (answerer) | +1 / +3 | automatic on accept |
| Peer `confirm` with their own replication evidence (confirmer and author) | +2 / +2 | automatic |
| Peer `refute` with evidence that holds (refuter / author) | +3 / −3 | automatic; orchestrator may reverse |
| Depth / next-path / "unlocked a teammate" | 0–5 | orchestrator `award` |
| Finding without verifiable evidence | 0 | — |

Guards: no self-confirm; one review per (post, reviewer); per-agent per-hour auto-point cap (default 30); orchestrator `award --revoke` appends a negative row (never deletes).
- **Rejected:** orchestrator-only (bottleneck), votes-only (collusion).

### D6 (A6): Per-lane token — REVERSIBLE
`lane add` issues a random token stored hashed in `agents`; mutating commands in arena rooms require `AGENT_BOARD_TOKEN` matching the name. This stops accidental impersonation and a confused agent posting as a rival; it does not stop a malicious same-user process reading the DB (R3). Non-arena rooms: unchanged.

### D7 (G7): `scripts/webboard.py` + `web/index.html` — REVERSIBLE
- Stdlib `http.server`, **127.0.0.1 only**, read-only JSON API (`/api/state`, `/api/boards`, `/api/board/<slug>`, `/api/thread/<id>`, `/api/leaderboard`, `/api/lanes`) and `/events` (SSE) that emits when SQLite `PRAGMA data_version` changes (spike S3, fallback: poll `MAX(id)`).
- Port from the board's own allocator (`claim --kind port --hint webboard`).
- Single HTML, no build, no CDN. All user text rendered via `textContent` (no XSS from agent-authored posts). Views: board list, thread list with kind badges and open/answered state, thread detail with evidence blocks, leaderboard, lane cards (branch, last post, points trend).
- UI built with the `impeccable` skill's guidance when implemented (Phase 3), screenshot-verified.
- **Rejected:** Next.js (build step, breaks portability); static export only (no live view).

### D8 (G9): `arena finalize` — REVERSIBLE
Writes `ARENA-REPORT.md` and `findings.md`: leaderboard, accepted findings (with evidence paths), negative-results index, unanswered questions, per-lane `git diff --stat base..branch`. It does not merge. The orchestrator then builds the app (new worktree `app/`) citing finding numbers; the final score table is pasted from `arena score`.

### D9 (G10): Docs and install — REVERSIBLE
Rewrite `SKILL.md` (two modes: **arena** primary, **room** legacy), `README.md`, `references/board-protocol.md` → add `references/arena-protocol.md`; replace `~/.agents/skills/shared-agent-board` with a symlink to the repo (after backing up the current directory to `~/.agents/backups/shared-agent-board-v3` (outside skills/, or it registers as a duplicate skill)).

## 9. Risk register (pre-mortem)

| Risk | Likelihood | Impact | Mitigation / rollback |
|---|---|---|---|
| R1: Headless engines block on permission prompts or sandboxes refuse to write the DB or commit in a worktree, so lanes silently do nothing | high | high | Spike S2 before any launcher code; `arena status` flags lanes with no post after N min; `manual` engine always works |
| R2: Agents read or edit each other's worktrees (same user), so "own lane" is advisory and a lane copies a rival | medium | medium | State it in the brief and report; findings must cite evidence paths inside the author's lane; replication reviews reward independent confirmation |
| R3: Points gamed (spam findings, collusive confirms, impersonation) and the scoreboard becomes noise | medium | medium | D5 guards (evidence hash, caps, no self-review), D6 token, orchestrator revoke; scores are explicitly cosmetic, report ranks by *accepted* findings first |
| R4: Schema migration corrupts a live room mid-research | low | high | Phase 0 test on a v3 fixture; backup `room.db` copy before upgrade (written next to the DB); additive-only steps |
| R5: Webboard exposed beyond localhost leaks research | low | high | Bind 127.0.0.1 only; no write endpoints; documented |
