## 1. Context

The constructor is the current host's main agent. It creates one active goal revision with several research **ways**; its native subagents choose ways, experiment in their own lanes, and exchange findings through the shared forum. Several workers may select the same way and may switch with a reason. Competition rewards verifiable contributions; other workers' findings are reusable inputs. The user explicitly confirmed these choices and mandatory consideration of peer work without a quota of artificial answers. They also requested Markdown rendering on the webboard.

**Definition of done (PROPOSED acceptance contract):** a host-native run completes two rounds with at least two workers and two ways, demonstrates voluntary selection, a switch, a cross-worker evidence reuse or answer, visible checkpoints, and a goal-oriented comparison report; all classic behavior remains supported; Markdown renders safely without dependencies. Human observation confirms actual interaction, rather than treating unit tests as proof of agent behavior.

**Non-goals:** implementing in this planning session; launching other provider executables as a fallback; hosted services; hard sandbox isolation; automatic lane merges; model API/SDK integrations; a complete CommonMark engine; changing cosmetic points into a quality oracle. “Local” means subagents of the current host, not an offline model or a promise that inference runs on this computer.

**Constraints VERIFIED:** stdlib-only, additive migration with backup, mutations in `board.tx`, allocation through claims, localhost/read-only HTTP, append-only ledger, no `innerHTML`, no process-name killing (`AGENTS.md:10-23`; `scripts/board.py:163-171,257-340`; `scripts/webboard.py:25,127-147`).

**Assumed framing defaults:** keep legacy CLI engines available only through explicit old workflows; rollout uses opt-in `--mode native` until dogfood passes; cap experiments/rounds rather than claiming exact token accounting. No destructive migration or removal is proposed. Existing `docs/PLAN.md` remains the historical v4 design record.

## 4. Audit findings

1. **[Correctness] Incremental feed can omit backlog.** With `--since`, SQL still takes the newest `LIMIT` rows before reversing (`scripts/arena.py:433-438`). A consumer advancing to the returned maximum can permanently miss earlier unread posts. M0 fixes this without changing latest-window behavior when `--since` is absent.
2. **[Correctness] Generated answer example cannot execute as written.** Brief omits `--title` (`scripts/arena.py:190`), but `cmd_post` requires it (`:409`). A broken example obstructs the desired interaction.
3. **[Reliability] Native workers have no feedback/lifecycle controller.** `cmd_run` transmits one brief and returns (`scripts/arena.py:627-649`); running/silence rely on a PID (`:674-685`). This is a structural limitation, not proof of the cause of the user's observed silence.
4. **[Correctness/model gap] A finding's `--next` is not an answerable question.** It is `posts.question` text (`scripts/arena.py:383-386,399-401`); `pick` selects only `kind='question'` (`:454-459`). Preserve old semantics; native workers explicitly call `ask` for questions needing a reply.
5. **[Maintainability] Stale architecture instructions describe completed work as missing.** `docs/ARCHITECTURE.md:11-28,47,57,94` conflicts with implemented server, migration, digest and token checks (`scripts/webboard.py:177-185`; `scripts/board.py:257-340,361-376,1073-1089`).

No security exploit or live agent-behavior reproduction is asserted. Markdown is a new content boundary and receives its own explicit threat/verification contract below.

## 7. Design decisions

Everything in this section is **PROPOSED normative behavior**, not a claim of existing implementation. Every choice is REVERSIBLE by opting out of native mode or reverting code while retaining additive data. Schema upgrades still require a quiesced backup for any data rollback; do not restore an old backup over newly written work.

### D1 / Gap 1: Host owns scheduling; Python owns durable arena state

- Options: Python launcher/SDK bridge vs host skill instructions plus machine-readable manifests.
- Decision: extend `SKILL.md` with a concrete constructor protocol; Python emits dispatch manifests but never calls host tools. Use currently available native tools discovered from the live tool surface, not executable searches or hardcoded provider APIs (§3).
- Reversibility: **REVERSIBLE**, opt-in `arena.py init --mode native`; omitted mode preserves legacy behavior and engine flags. Native mode rejects `--engine`/`--cmd` launch overrides; never silently falls back. Legacy/manual rooms remain usable.
- Reject bridge: no verified bridge exists; SDKs violate zero-dependency constraint.
- `run` in native rooms prepares pending manifests only and explicitly reports “not spawned”; constructor performs tool calls. It validates all selected names before doing work, then processes names in sorted order with one transaction per worker: returns successful manifests plus structured per-worker errors, overall ok=false/exit1 if any failed, without rolling back successes or spawning anything. Re-running for an unbound prepared worker returns its existing manifest; running/checkpointed/already-bound prepared workers return active-attempt errors. No room-wide all-or-nothing behavior. Every returned unbound manifest still requires host inventory/reconciliation before an actual spawn; replaying run is never authorization to double-spawn. `stop` returns a native interruption request and records nothing as stopped until host observation is reconciled. Explicit legacy subprocess commands remain unchanged.

### D2 / Gap 2: Goal revision -> independent ways -> worker choice history

- Options: one lane per fixed strategy vs many workers selecting a shared way catalog.
- Decision: retain `goals` as revision history; constructor attaches a structured config and creates ways for the current goal ID. Each worker selects one way per attempt; separate lanes remain per worker. Way is a research approach, board is a discussion topic, lane is a filesystem workspace; none is a substitute for another.
- Reversibility: **REVERSIBLE**, additive schema v5; old rows remain nullable/unassociated.
- Constructor alone adds/closes ways; workers can propose a way with a `note` and constructor may add it. Different ways may reach the same outcome by different experiments. No exclusive way lock, no forced balancing. Constructor displays uncovered ways but does not silently reassign volunteers.
- `ways choose --way SLUG --attempt ID --reason TEXT` appends a choice; switching requires a nonempty reason and stays in the same lane. One attempt uses its latest choice; posts capture choice at creation and never change retrospectively. Closing a way prevents new selections; workers already there may checkpoint and select another next attempt.
- Existing `board.py goal` still appends revisions. If it changes during native work, old attempts may publish/checkpoint only against their original revision, then must stop before another experiment. New preparation requires configuring current revision and adding its ways. Reports keep older results labeled with their original revision; no silent rebinding.
- Reject fixed lanes: contradicts user-confirmed voluntary selection/sharing/switching.

### D3 / Gap 3: Bounded rounds with durable inbox receipts and checkpoints

- Options: one indefinitely running worker prompted to poll vs short native turns controlled by constructor.
- Decision: each worker turn has at most one experiment, followed by publication, peer consideration and a checkpoint. Defaults: 3 workers requested, 3 rounds maximum and at most 2 generations per round, 1 experiment per turn; actual concurrency is bounded by verified host slots. Round is per-worker ordinal; constructor runs a wave, reconciles all its attempts, then starts the next wave. These are effort limits, not exact tokens or hard preemption.
- Reversibility: **REVERSIBLE**, native only; legacy post/feed commands still work.
- Worker loop: source its env explicitly for shell commands, use its absolute lane cwd, `native begin`, drain inbox, inspect current ways/criteria, choose way, perform bounded experiment, `post`/`ask`/`answer`/`review` as useful, drain inbox again, then `native checkpoint --file @checkpoint.json`, return checkpoint ID to constructor. Use `ask` for actionable questions; legacy `--next` remains a next-step annotation. Do not auto-create questions from all old findings.
- Inbox returns full post bodies/evidence plus review/answer-acceptance updates and current goal/ways. Pagination uses independent monotonic post/review watermarks; acceptance is a full current snapshot because an older answer may be accepted later (see storage contract). Constructor/worker never advance acknowledged cursors on a plain read. A final drained receipt supplies safe cursor cutoffs for checkpoint.
- A checkpoint contains: summary, emitted post numbers, selected way, outcome `progress|blocked|exhausted|candidate`, next action, inbox receipt ID, peer dispositions. Each disposition is `answer|reuse|review|defer|not_applicable` with a target post and reason; action dispositions reference the created answer/link/review and are DB-validated. Peer candidates are the union of posts from the entire receipt parent chain for the final drain (back to its root at the last acknowledged checkpoint), plus open-peer-question snapshot entries; validation must not inspect only the last page. If this union has any other worker's question/finding/negative, require at least one disposition; otherwise allow `no_peer_material`. This proves recorded consideration, not understanding or truth.
- Meaningful unanswered peer questions and peer results are explicitly surfaced; constructor routes a relevant question as a prompt suggestion, but the worker chooses what to answer. There is no answer quota, no points for receipts, deferrals or chatter. Repeated deferral is shown to constructor, not converted to fabricated answers.
- `checkpoint` rejection leaves attempt running and receipts unacknowledged. Exact retry is idempotent, conflicting retry fails. A blocked worker still checkpoints with a reason; it need not invent evidence.
- Reject long-running workers: host lifecycle and prompt-only polling give no durable boundary for recovery or discussion checks.

### D4 / Gap 4: Repair feed and executable brief before native functionality

- Options: replace feed API vs retain commands and fix incremental ordering.
- Decision: when `--since` is explicitly supplied (including 0), select `p.n > since ORDER BY p.n ASC LIMIT limit`; no reverse. When absent, retain latest-window selection reversed for chronological display. Reject negative `since`, and limits outside 1..500 with a clear CLI error. Add `--title` to answer example and `--full` to the brief's read instruction.

- Reject replacing feed: breaks classic clients unnecessarily. Native inbox uses its own receipts, not an implicit feed acknowledgement.

### D5 / Gap 5: Explicit provenance; reuse does not imply independence

- Options: copy text with informal attribution vs stored post-to-post links.
- Decision: add repeatable `--source POST_N` on native `post`/`answer`; same-transaction `post_links(target_post_id, source_post_id, relation='uses')`. A link points only to an existing earlier post in this room; reject self, duplicate and nonexistent links. Display author/goal/way/status of source; cross-way and cross-revision reuse permitted and labeled. Archived native evidence remains addressable even if its origin lane is retired. This durability guarantee applies only to evidence_files archives, never to unarchived historical paths. Historical source posts remain linkable, but APIs/UI/reports label their evidence unarchived and availability unverified; a source link alone does not upgrade that status.
- Reversibility: **REVERSIBLE**, optional links on legacy posts.
- No automatic new points for a source link. Existing finding scoring remains unchanged for compatibility; constructor may use existing bounded `award` after checking genuine downstream value. Reuse is not a `review confirm`; copying a source's log does not prove independent replication.
- Native evidence files are copied at publication into a claimed room evidence directory using content hashes and atomic replace; post retains original absolute path, original digest and stable copy path in a new `evidence_files` table. Apply to new evidence on native posts/reviews; legacy text remains intact. Do not import arbitrary directories or auto-delete lane artifacts. Identical bytes reuse the content-addressed blob without implying new independent work. Store only regular readable files up to 10 MiB each (checked before and during bounded read); reject oversized native evidence with a clear error. Legacy evidence semantics remain unchanged.
- Reject automatic reuse points: encourages citation spam and self-referential point farming. Quality/synthesis decisions stay evidence-based and separate from points.

### D6 / Gap 6: Attempts with host reconciliation and bounded recovery

- Options: treat host IDs as PIDs vs persist attempt ID/generation and host observations.
- Decision: append attempts with per-worker ordinal/generation; constructor owns reservation, host binding and observed terminal outcomes; worker token owns begin/checkpoint. No worker recursively spawns more agents. One active attempt per worker across all goals, atomic uniqueness guard. Preparation is scoped to `(worker,goal_id)`: first round=1,generation=1. After finished, advance round and reset generation=1. After failed/interrupted/unresponsive, retry the same round with generation+1 if below max_generations; otherwise advance round and reset generation. Reject a round exceeding max_rounds. Thus default maximum is 6 attempts per worker per goal, including failed attempts; retries are never unlimited. Constructor may finish earlier when candidate/exhausted/blocked work warrants synthesis. Core allocation/budget guards ship in M1; M2 adds failure/resume stress tests, not a second allocation policy.
- Reversibility: **REVERSIBLE**; native lifecycle independent from old `lanes.pid`.
- Lifecycle: `prepared -> running -> checkpointed -> finished`; failures/interruption/unresponsive observed by constructor may terminate prepared/running/checkpointed attempts. `checkpointed` remains active until host turn has returned. Constructor binds host reference after spawn; worker may begin before bind (spawn/bind race). Worker publication, ask/answer/review, choice and first checkpoint are allowed only in running state; begin transitions prepared->running and is idempotent only while already running. Pure reads (feed/status/ways list) are allowed in all states. `native inbox` creates durable receipts and is therefore allowed only in running state; before begin or after checkpoint/terminal it fails without writes and directs the caller to pure feed/status instead. After checkpointed no further worker mutation is allowed, except identical checkpoint replay returning its existing ID without writes (also allowed after terminal observation). Bind is idempotent even if worker already checkpointed/finished, but never overwrites a different host reference. Reuse a host subagent with followup only after prior turn is observed complete; otherwise spawn replacement after terminal reconciliation.
- Before a host call reserve an attempt and persist manifest. After call bind host reference. If a crash loses the call result, do not blindly spawn again: inspect host inventory, bind matching reference if provable, or record `needs_reconciliation` diagnostic and stop that worker pending manual host inspection. Elapsed time alone never proves termination.
- Old attempts cannot publish as new work after termination: native worker mutations require `AGENT_BOARD_ATTEMPT` matching the active attempt. Read commands remain available. Legacy mode ignores this variable. Expiry marks stale/attention only; constructor uses native tools to inspect/interrupt before replacing. In this host interruption ends the current turn; do not call it thread destruction.
- Constructor checks after each bounded wait (at most 60s in this app) for new board updates and host results. Let timeout=goal_config.idle_seconds (default300). If an attempt has no checkpoint and now-prepared_at >= timeout, send one native reminder with inbox pointer; after now-last_reminder_at >= timeout inspect/interrupt and reconcile as unresponsive if still no response. Posts/read receipts do not reset these intervals. A prepared attempt with an unknown host reference uses the existing needs_reconciliation/manual-inventory path instead of attempting to message an unknown agent. Persist reminder time/count so resume does not spam. Host capability absence is explicit unsupported mode, never fallback to another executable.
- Finalize snapshots only after all native attempts are terminal and host completion/interruption has been observed. Serialize native prepare and finalize with one stable, never-replaced per-room lock file: native init claims a path with kind=path/create=False/hint=native-control-lock through B.allocate in tx, stores it in meta.native_control_lock, then opens that exact file (no guessed lock path). Both operations take stdlib fcntl.flock LOCK_EX|LOCK_NB before any B.tx; contention returns a retryable busy error, not an indefinite wait. Prepare holds it through reservation commit; finalize holds it from terminal-attempt recheck through all git snapshots and atomic report-file replacements. Therefore a prepared attempt committed first makes finalize refuse; finalize acquiring first excludes new reservations/spawns until snapshot completion. Do not hold a SQLite write transaction over git work: materialize report DB data in one read snapshot after terminal check, then do filesystem work under the file lock. DB results and report identify their captured_at timestamp. Lock order is always file lock -> DB transaction, never reverse. OS close/process exit releases lock; failures close in finally; never unlink or rotate the lock file while room exists. Preview uses the same lock but allows active attempts and performs no git snapshot, remains explicitly incomplete. Legacy finalize unchanged. Native init provisions this lock before emitting native mode as ready; missing lock metadata in a native room is a configuration error, never an invented fallback path. A `finalize --preview` new option produces an explicitly incomplete report without snapshotting for inspection while workers run.
- Reject PID reuse: native host reference is opaque; passing it to `killpg` is invalid.

### D7 / Gap 7: Compare ways using criteria, not score totals

- Options: choose highest scorer vs constructor-authored evaluation referencing posts.
- Decision: constructor submits a synthesis JSON for a goal revision, with each criterion assessed `met|not_met|unknown`, evidence post numbers, way-level summary, contradictions, unresolved questions, recommendation and rationale. Validate references and require at least one evidence post for `met`; do not pretend schema validation evaluates truth. Constructor can return “no supported winner”. Way summaries may combine peer evidence.
- Reversibility: **REVERSIBLE**. Existing report/score output stays; native adds goal revision, way history, participation/dispositions, provenance, criteria matrix and run completeness. Unreviewed/refuted findings are visibly labeled; score alone never establishes success.
- Observer API adds `/api/ways`, `/api/native`, `/api/synthesis`; `/api/lanes` preserves old keys, adds runtime_kind, attempt_state, way, last_checkpoint, stale and attention. Native `running` comes from current persisted host observation and is labeled observed time, not a live guarantee. Native status never checks `pid_alive` for its worker.
- Reject autonomous DB-selected winner: evidence presence does not prove criteria satisfaction.

### D9 / Gap 9: Bounded Markdown AST rendered with safe DOM nodes

- Options: bundled third-party Markdown/sanitizer vs a documented small subset parsed in Python and built with existing DOM helpers.
- Decision: new stdlib-only `scripts/markdown_view.py` provides `parse_markdown(text)` -> version-1 JSON node tree. `webboard.py` adds `body_blocks` to thread posts, `note_blocks` to reviews and `goal_blocks` to state; raw fields remain unchanged. Browser `renderMarkdown(nodes)` uses a fixed switch and `createElement`/`textContent`/`append`, never HTML-string APIs or user-supplied tag names. Zero CDN/build dependencies.
- Reversibility: **REVERSIBLE**, fallback raw text when nodes absent/unsupported. Browser URLs and attributes are set only by the allowlisted renderer.
- Supported subset: ATX headings #..###### mapped to h4..h6 within thread (clamp levels to preserve page hierarchy), paragraphs, blank-line separation, one-level unordered/ordered lists, blockquotes, fenced triple-backtick code with optional displayed language label (no syntax highlighter), horizontal rules, simple pipe tables (header + delimiter + rows; no row/col spans), inline `**strong**`, `*em*`, backticks, and `[label](URL)` links. Tables/lists/quotes may contain inline nodes but no nested block structures. Unsupported/nested/ambiguous syntax renders literally. Unclosed code fence consumes to end as code. Inline delimiters do not cross newlines; unmatched delimiters remain text. No images, autolinks, raw HTML, reference links, embedded media, task widgets or executable extensions.
- Node schema: block `{type:'paragraph'|'heading'|'blockquote', children:inline[], level?:int}`; list `{type:'list',ordered:bool,items:inline[][]}`; code `{type:'code',text:str,language:str}`; rule `{type:'rule'}`; table `{type:'table',header:inline[][],rows:inline[][][]}`. Inline `{type:'text'|'code',text:str}`, `{type:'strong'|'em',children:inline[]}`, `{type:'link',href:str,children:inline[]}`. Unknown node type renders its text as text, never interprets a tag. Return `{version:1,blocks:[...]}`.
- Block precedence: fenced code, heading, rule, table header+delimiter, list run, quote run, paragraph. Inline precedence: escaped punctuation, code, link, strong, emphasis, text; max inline nesting 4. Backslash only escapes Markdown punctuation. Table cells split on unescaped pipes outside inline backticks; leading/trailing pipe optional, delimiter cells match `:?-{3,}:?`; fixed header column count, short rows pad empty, excess cells join literally into final cell. No alignment attributes from text.
- URL policy: accept only absolute http/https with nonempty hostname, no userinfo, no raw ASCII control/whitespace/backslash, or exact local fragment `#/post/[1-9][0-9]*`. Require case-insensitive literal `http://` or `https://` prefix before `urlsplit`; no entity/percent decoding of the scheme. Everything else remains visible label plus literal destination as text, not an anchor. External links use rel=noopener noreferrer and target=_blank. Renderer repeats scheme/control checks before href assignment as defense against malformed node data. Image syntax remains literal and causes no network fetch.
- Evidence/digests/commands in evidence fields remain plain `<pre>`; titles/agent names/board names/ledger reasons/next-question text remain plain text. Markdown applies to goal/body/review notes only. Raw HTML such as `<img onerror=...>` is displayed literally. A Raw/Rendered toggle on prose is local viewing state, not an HTTP write.
- Bound processing: at most 100 KiB UTF-8 per prose input and 5,000 nodes; on exceed, return one plain text code node containing original text truncated at 100 KiB plus visible truncation notice, with raw toggle preserving access to original API field. No recursive regex over nested blocks. Scope CSS to `.md` so existing dashboard `ul`, `table`, `th`, `td`, `.msg p` rules do not suppress bullets or distort prose tables. Code/table wrappers scroll horizontally; links have keyboard focus; narrow view stays within viewport. Preserve existing paper/ink typography, not a full visual rebrand.
- Reject third-party renderer: violates zero dependencies/build constraint; full CommonMark compliance is not required by this request. This subset is named explicitly in docs so limitations are observable.
